# 🌌🇮🇷 اتوماسیون کانال تلگرام «Daily Science, Space & Reddit»

سیستم کاملاً **رایگان و پایدار** روی GitHub Actions که روزانه دو دسته محتوا را **فقط به فارسی شیرین** در [@daily_sciences](https://t.me/daily_sciences) منتشر می‌کند — با ایموجی و هشتگ‌های مینیمال و حرفه‌ای:

| Workflow | زمان (تهران) | محتوا |
|---|---|---|
| **Reddit Top Daily Post** | هر روز ۱۳:۳۰ (+ پشتیبان ۱۵:۰۰) | ۵ پست برتر r/science+space+astronomy: عنوان فارسی جذاب + خلاصه + عکس + آمار با ارقام فارسی + هشتگ |
| **NASA APOD Daily Post** | هر روز ۲۱:۰۰ (+ پشتیبان ۲۳:۰۰) | عکس/ویدئوی روز ناسا: عنوان فارسی + تاریخ شمسی + اعتبار + توضیح کامل فارسی + هشتگ |

## قالب پست‌ها (فقط فارسی)

**پست ناسا** — کپشنِ عکس/ویدئو:

```
🌌 عکس نجومی روز ناسا

🪐 صندوقچه‌ای گنج در سحابی کارینا

📅 پنجشنبه ۲۶ شهریور ۱۴۰۵
🔭 اعتبار: NASA JPL-Caltech

#نجوم #سحابی_کارینا
```

سپس یک پیام جداگانه با ترجمهٔ کامل و روان توضیحات ناسا.

**پست ردیت**:

```
🦠 واکسیناسیون برای پیشگیری از RSV در نوزادان

مطالعه جدید نشان می‌دهد واکسیناسیون می‌تواند نوزادان را در برابر این ویروس تنفسی محافظت کند.

⬆️ ۱۱٫۹ هزار امتیاز • 💬 ۲۳۴ دیدگاه • r/science

#واکسن #سلامت
```

ایموجیِ ابتدای عنوان و هشتگ‌ها را خودِ هوش مصنوعی متناسب با موضوع هر پست انتخاب می‌کند (مینیمال و هدفمند؛ نام‌های خاص مثل NASA یا r/science به همان شکل می‌مانند).

## معماری ترجمه (`llm_translator.py` + `persian_utils.py`)

کلید LLM به‌صورت خودکار تشخیص داده می‌شود: اول **Groq** (api.groq.com) سپس **xAI Grok** (api.x.ai) امتحان می‌شود و اولین سرویس پذیرنده با بهترین مدل موجود استفاده می‌گردد. خروجی ترجمه اعتبارسنجی می‌شود (متن فارسی، طول مناسب، ایموجی معتبر، هشتگ تک‌توکنی) و در صورت ناموفق‌بودن، اجرا **عمداً شکست می‌خورد** تا اجرای پشتیبان دوباره تلاش کند — چون سیاست کانال «فقط فارسی» است و هرگز پست انگلیسی ارسال نمی‌شود.

### خط تولید دو مرحله‌ای برای فارسی صحیح

برای اینکه ترجمه همیشه فارسی روان و بی‌غلط باشد، هر پست از **دو مرحله** رد می‌شود:

۱. **مترجم** — مدل LLM با پرامپت قواعد سخت‌گیرانه (ترجمهٔ معنا نه کلمه‌به‌کلمه، اصطلاحات استاندارد ویکی‌پدیای فارسی، نیم‌فاصله و کسرهٔ اضافهٔ صحیح، ممنوعیت کلمات ساختگی) و **واژه‌نامهٔ اجباری** (مثلاً Andromeda=آندرومدا هرگز آندروید، Messier=مسیه، Pinwheel=فرفره) ترجمهٔ اولیه را می‌سازد
۲. **ویراستار** — فراخوانی دوم روی همان مدل با نقش «ویراستار سخت‌گیر فارسی»: پیش‌نویس را با متن انگلیسی مقایسه و کلمات بی‌معنی، ترجمه‌های تحت‌اللفظی و خطاهای گرامری را اصلاح می‌کند

مدل فعال (بعد از مقایسهٔ زندهٔ کیفیت در سپتامبر ۲۰۲۶/۱۴۰۵): **qwen/qwen3.8-27b** برای هر دو مرحله، با پشتیبان gpt-oss-120b. محدودیت توکن خروجی qwen (حدود ۱۰۰۰ توکن/دقیقه) با پیس‌بندی و backoff طولانی برای خطای 429 مدیریت می‌شود.

### ورک‌فلو «Translation QA» (دستی)

برای مقایسهٔ کیفیت مدل‌های مختلف یا تست ترجمه بدون ارسال: **Actions → Translation QA → Run workflow**. این ابزار همان پرامپت‌های تولیدی را روی APOD روز و برترین پست‌های Reddit اجرا و خروجی کامل فارسی را در لاگ چاپ می‌کند — بدون ارسال به تلگرام و بدون دست‌زدن به stateها.

`persian_utils.py` ابزارهای مشترک فارسی را می‌دهد: تبدیل تاریخ میلادی به **شمسی** (با روز هفته)، **ارقام فارسی** (۱۱٫۹ هزار)، انتخاب ایموجی و اعتبارسنجی هشتگ‌ها (هشتگ باید حرف فارسی داشته باشد — هشتگ لاتین حذف می‌شود).

## معماری داده Reddit (`reddit_top_bot.py`)

ردیت IPهای دیتاسنتر (از جمله GitHub Actions) را در endpoint های عمومی JSON بلاک می‌کند (خطای 403). اسکریپت لایه‌بندی‌شده این‌ها را به‌ترتیب امتحان می‌کند:

1. **JSON عمومی** (www/old/api.reddit.com) — داده زنده، اگر IP بلاک نباشد
2. **OAuth رسمی** — اگر `REDDIT_CLIENT_ID` و `REDDIT_CLIENT_SECRET` تنظیم شده باشند (داده زنده، بدون تأخیر)
3. **آینه Arctic-Shift** (بدون نیاز به ثبت‌نام) — امتیازها حدوداً ۳۰ ساعت بعد از ایجاد پست به‌روز می‌شوند؛ پنجره ۵۴ ساعته + ضدتکرار تضمین می‌کند هر روز ۵ برترینِ واقعیِ منتشرنشده ارسال شود (با حدود یک روز تأخیر)
4. **آینه PullPush** (بدون نیاز به ثبت‌نام) — جانشین Pushshift؛ لایهٔ پشتیبانِ آینهٔ قبلی با همان منطق پنجره ۵۴ ساعته
5. **فید RSS خودِ ردیت** (بدون نیاز به ثبت‌نام) — برترین‌های زندهٔ همان روز؛ فاقد عدد امتیاز/دیدگاه است، پس پست‌های این منبع بدون خط آمار (فقط r/... ) منتشر می‌شوند — هرگز عدد جعلی چاپ نمی‌شود

برای حذف تأخیر و دریافت داده کاملاً زنده: یک «اسکریپت اپ» رایگان در reddit.com/prefs/apps بسازید و دو Secret بالا را اضافه کنید (۲ دقیقه).

## تاب‌آوری در برابر قطعی آینه‌ها

اگر همهٔ منابع یک اجرا شکست بخورند (مثلاً قطعی چندساعتهٔ Arctic-Shift با خطای 522):

- **در همان اجرا**: کل زنجیرهٔ منابع تا ۳ بار با فاصلهٔ ۴ دقیقه دوباره امتحان می‌شود (`FETCH_ROUNDS` / `FETCH_ROUND_WAIT`)
- **در طول روز**: workflow ساعت‌های ۱۰:۰۰، ۱۱:۳۰، ۱۳:۰۰، ۱۴:۳۰، ۱۶:۰۰ و ۱۷:۳۰ UTC اجرا می‌شود؛ سهمیهٔ روزانه و ضدتکرار باعث می‌شوند اجراهای بعدی فقط «کسری» را تکمیل کنند — پس به‌محض بازیابی هر منبع، پست‌های عقب‌مانده همان روز منتشر می‌شوند و هیچ‌وقت تکراری ارسال نمی‌شود
- **فید RSS ردیت معمولاً حتی هنگام قطعی هر دو آینه در دسترس است** (فیدها برخلاف JSON از IPهای دیتاسنتر بلاک نمی‌شوند) — پس حتی در بدترین حالت، برترین‌های همان روز بدون خط آمار منتشر می‌شوند

## ضدتکرار، سهمیه روزانه و پایداری

- `state.json` (ناسا) تاریخ آخرین APOD ارسال‌شده را نگه می‌دارد؛ `state_reddit.json` (ردیت) ۱۵۰ شناسهٔ آخر + **سهمیهٔ روزانه** (`posts_today`) را — اجراهای پشتیبان فقط کسری را که اجرای اصلی نتوانسته تکمیل می‌کنند، نه تکرار
- اگر ترجمهٔ فارسی در دسترس نباشد، اجرا شکست می‌خورد و پشتیبان ۲ ساعت بعد دوباره تلاش می‌کند (هرگز پست انگلیسی/دوزبانه ارسال نمی‌شود)
- کامیت روزانه stateها ریپو را همیشه «فعال» نگه می‌دارد (جلوگیری از خاموشی ۶۰روزه GitHub)
- NASA API اگر ورودی امروز را نداشت، آخرین APOD موجود را می‌گیرد؛ عکس‌های بزرگ/پانوراما خودکار فشرده می‌شوند تا همیشه «عکس» ارسال شوند نه «فایل»

## 🛡 نگهبان کانال (`channel_guardian.py`) — تضمین سلامت همیشگی

اسکریپت اپ یکپارچه که هر روز دو بار صحت واقعی کانال را راستی‌آزمایی می‌کند و هر خللی را خودکار ترمیم می‌کند. این اسکریپت به فایل‌های state اعتماد نمی‌کند — محتوای واقعی کانال را از پیش‌نمایش عمومی `t.me/s/daily_sciences` می‌خواند و با state تطبیق می‌دهد:

| حالت | کشف | ترمیم خودکار |
|---|---|---|
| پست غایب | state + کانال هر دو خالی | اجرای همان بات (پُرکردن/تکمیل سهمیه یا `--date` برای روزهای جا‌مانده) |
| پست تکراری | عنوان یکسان ردیت در ۴۰ ساعت اخیر، یا تاریخ شمسی یکسان APOD | حذف نسخهٔ دیرتر + اصلاح سهمیه ۱به۱ |
| پست شکسته | APOD بدون عکس/ویدئو | حذف + پاک‌کردن state + ارسال مجدد سالم |
| ناسازگاری state/کانال | state می‌گوید posted ولی کانال نه | فقط هشدار (exit 1 → ایمیل GitHub) — هرگز ریسک تکرار نمی‌کند |

- **زمان‌بندی**: ۰۹:۵۵ (بررسی APOD دیروز/امروز + پُرکردن روزهای جا‌مانده)، ۲۲:۱۰ و ۲۳:۰۵ UTC (بررسی کامل: سهمیه ۵/۵ ردیت + تکراری + APOD امروز)
- **گروه concurrency مشترک** `channel-pipelines` بین هر سه workflow → هیچ دو اجرایی هم‌زمان نمی‌شوند؛ رقابت state (که یک‌بار باعث ۵ پست تکراری شد) از امروز غیرممکن است
- **قانون طلایی ضدتکرار**: نگهبان هرگز خودش مستقیم پست نمی‌فرستد؛ فقط از طریق بات‌های محافظت‌شده با state؛ حذف فقط با تطبیق قوی (عنوان یا تاریخ شمسی یکسان)؛ backfill روزهای قدیمی فقط با دلیل مثبت از خود کانال
- **حالت‌ها**: `--dry-run` (فقط گزارش)، `--skip-reddit`، `--no-delete`، `--diag` (عیب‌یابی)؛ ورودی‌های دستی workflow هم همین‌ها هستند
- تست آفلاین: `python test_guardian_logic.py` (۶۵ سناریو)

## دستورات مفید (Actions → Run workflow)

- **Reddit Top Daily Post**: تیک `dry_run` = عیب‌یابی (دریافت + ترجمه بدون ارسال)، تیک `force` = نادیده‌گرفتن ضدتکرار و سهمیه
- **NASA APOD Daily Post**: تیک `force` = ارسال مجدد همان روز، تیک `dry_run` = پیش‌نمایش ترجمه بدون ارسال
- **Channel Guardian**: تیک `dry_run` = فقط راستی‌آزمایی بدون هیچ تغییری؛ `force_reddit_check` = بررسی سهمیه ردیت خارج از بازهٔ شب
- **Channel Cleanup**: حذف پیام‌های خاص کانال با شمارهٔ پیام (شناسه‌ها از t.me/s/daily_sciences قابل مشاهده‌اند — فرمت daily_sciences/NNN)

اجرای محلی:

```bash
pip install -r requirements.txt
python reddit_top_bot.py --diag        # عیب‌یابی اتصال LLM + منابع Reddit
python reddit_top_bot.py --dry-run     # پیش‌نمایش بدون ارسال
python nasa_apod_bot.py --dry-run
python channel_guardian.py --diag      # پیش‌نمایش کانال + NASA API
python channel_guardian.py --dry-run   # راستی‌آزمایی کامل بدون تغییر
```

## تغییرات (۲۰۲۶-۱۰-۲۹) — 🔄 سومین جابه‌جایی فرمت: تاریخِ روز-اول؛ ریشه‌کن‌سازیِ «فرض ترتیب تاریخ» برای همیشه

- **باگ (گزارش مالک: امروز هم پست ناسا نیامده)**: ناسا امروز سومین فرمت URL را در دو هفته سرو کرد — `…/image-article/apod-29-october-2026-the-horns-of-venus/` (**روز-ماه-سال**؛ روز و سال جابه‌جا!) به‌جای `apod-2026-october-28-…`. هر دو پارسر دیسکاوری (فید + صفحهٔ خانه) با regex «سال-ماه-روز» سخت‌گیر تاریخ را می‌خواستند → مدخل امروز نامرئی → «newest entry = دیروز» → «already posted» → **خروج موفقِ بی‌صدا برای چهارمین اجرای پیاپی** (اسلات 16:15 + سه دیسپچ نجات meta-guardian در 17:47/18:13/18:39). APOD امروز («The Horns of Venus») از 04:05 UTC منتشر شده بود و سالم در فید بود — فقط فرمت slug عوض شده بود. `og:title` صفحه هم همان روز جابه‌جایی را داشت («APOD: 29 October 2026 - …») → پارسر og:title هم مرد.
- **ریشهٔ تکرارشونده و راه‌حل ساختاری**: هر فیکس قبلی «یک شکلِ بیشتر» را هاردکد می‌کرد و ناسا شکل بعدی را می‌آورد. این‌بار دو قاعدهٔ order-agnostic جایگزین هر فرض ترتیبی شدند: (۱) **دیتای ورودی فید از `<pubDate>` می‌آید** — فرمت RFC-822 پایدار CMS که کاملاً مستقل از slug است؛ slug فقط fallback است و اگر هر دو پارس شوند و اختلاف داشته باشند pubDate برنده می‌شود (با لاگ هشدار). حالا هر فرمت URL آینده به‌طور خودکار بی‌اثر می‌شود. (۲) **پارسر slug/og:title کلاس‌بندی توکنی**: سه توکن بعد از «apod» (یا در og:title) با ماهیت‌شان شناسایی می‌شوند — عدد ۴ رقمی = سال، نام ماه = ماه، عدد ۱-۲ رقمی = روز — در هر ترتیبی (سال-اول، روز-اول، ماه-اولِ فرضی، اسلش یا خط تیره). لینک‌های صفحهٔ خانه هم به هر نوع article می‌پذیرند (نه فقط image-article).
- **رفع‌های جزئی همراه**: `<title>` صفحه به‌عنوان fallback دوم og:title (همان منطق order-agnostic)؛ لاگ هشدار برای مدخل‌های تاریخ‌ناپذیر فید؛ اعتبارسنجی منطقی روز (1-31) و سال (1995-2100).

## تغییرات (۲۰۲۶-۱۰-۱۸) — روزهای YouTube دیگر هرگز بدون پست نمی‌مانند

- **باگ (گزارش مالک: پست امروز ناسا در کانال نیامده — دوباره)**: APOD روز ۲۰۲۶-۱۰-۱۸ («Sonified: Eagle Nebula Pillars») یک **روز ویدئویی YouTube** است — پخش‌کننده یک `<iframe>` یوتیوب است، نه `<video>` ناسا. yt-dlp روی آی‌پی‌های GitHub Actions به دیوار «Sign in to confirm you're not a bot» یوتیوب می‌خورد (بلاک دائمی و قطعی، نه گذرا — هر ۵ اجرای روز شکست خورد)، و کل زنجیرهٔ جایگزین هم مرده بود: `thumbnail_url` فقط از صفت `poster` تگ `<video>` می‌آمد که در روزهای iframe وجود ندارد؛ `thumbnailUrl` خودِ `VideoObject` (پوستر رسمی روی CDN خود ناسا!) خوانده نمی‌شد؛ و بندانگشتی واقعی `hqdefault` یوتیوب (تصویر ۴۸۰×۳۶۰ واقعی با ~۱۲KB) با قاعدهٔ قدیمی «کمتر از ۱۵,۰۰۰ بایت = placeholder» رد می‌شد. نتیجه: «No usable media prepared» در هر پنج اجرا و کانال بدون پست.
- **رفع ۱ — پوستر از خود صفحه**: `scrape_apod_web` حالا `VideoObject.thumbnailUrl` (رشته یا لیست، با unescape موجودیت‌های HTML) را به‌عنوان پوستر استخراج می‌کند و برای روزهای ویدئویی یک **زنجیرهٔ کامل کاندیدای پوستر** می‌سازد: پوستر `<video>`/`thumbnailUrl` → نسخهٔ اصلی `og:image` → تصویر dynamicimage نیوزآرتیکل → خود `og:image` — همگی روی CDN خود science.nasa.gov (همان میزبانی که اسکرپ موفق رویش انجام شده؛ پس به دقت خودِ اسکرپ قابل‌اتکاست) و با فیلتر لوگو. کاندیداها در `thumbnail_url` + `extra_image_urls` دیکشنری ویدئو می‌نشینند.
- **رفع ۲ — اعتبارسنجی با decode نه حجم بایت**: `download_thumbnail` حالا هر کاندیدا را با `_image_size_ok` (بازکردن واقعی تصویر با Pillow و کنترل ابعاد) می‌سنجد؛ `hqdefault` واقعی ۴۸۰×۳۶۰ (حتی زیر ۱۵KB) پذیرفته می‌شود و placeholder خاکستری ۱۲۰×۹۰ رد می‌شود. کاندیداها به‌ترتیب: پوستر ناسا → `extra_image_urls` → `maxresdefault` → `hqdefault` → آینهٔ `img.youtube.com`؛ همه با هدر مرورگر.
- **رفع ۳ — لایهٔ تصویری برای روزهای ویدئویی**: اگر پوستر و بندانگشتی‌ها همه شکست بخورند، `prepare_media` یک گذار مستقل دیگر دارد: همان ماشین‌آلات روزهای عکسی (`download_images` با اعتبارسنجی decode و چک Content-Type) روی کاندیداهای پوستر — سه لایهٔ مستقل روی یک میزبان قابل‌اتکا.
- **رفع ۴ — محافظ لوگوی contentUrl**: `contentUrl` در ld+json روزهای YouTube می‌تواند لوگوی PNG سایت ناسا باشد؛ حالا فقط وقتی «ویدئو» پنداشته می‌شود که پسوند فایل رسانه‌ای واقعی (mp4/m4v/webm) داشته باشد و مسیرش لوگو نباشد — وگرنه `embedUrl` پخش‌کننده ملاک می‌ماند.
- **رفع ۵ — تلاش دوبارهٔ yt-dlp با کلاینت‌های دیگر**: پس از شکست اول (بلاک بات)، یک تلاش دیگر با `player_client=tv,android` انجام می‌شود که از آی‌پی دیتاسنترها اغلب موفق است؛ اگر آن هم نشد، پوستر جایگزین می‌شود. اگر ویدئو واقعی بیاید همچنان `sendVideo` برنده است.
- **رفع ۶ — لینک تماشا در پست‌های پیش‌نمایش**: وقتی روز ویدئویی با تصویر پوستر پست می‌شود، کپشن فارسی و انگلیسی حالا خط «▶️ تماشای ویدئو: …» با URL نرمال‌شده (embed → watch) دارد تا خواننده واقعاً بتواند ویدئو را ببیند — پستِ پیش‌نمایش دیگر «ناقص» نیست.

- **رفع ۱ — روزهای ویدئویی**: `scrape_apod_web` حالا `VideoObject.contentUrl` (فایل MP4 مستقیم) و `embedUrl` (پخش‌کننده‌های YouTube/Vimeo که yt-dlp می‌فهمد) را استخراج می‌کند؛ ویدئو بر همهٔ کاندیداهای تصویری اولویت دارد و دیکشنری با `media_type: video` برمی‌گردد تا مسیر ارسال ویدئو (sendVideo → بندانگشتی) همیشه همانند روزهای YouTube کار کند. `download_video` هم مسیر دانلود مستقیم HTTP برای فایل‌های mp4 (HEAD چک حجم + سقف ۴۸MB وسط دانلود + `Accept-Encoding: identity` چون CDN روی HEAD گلیپ می‌زند و content-length را می‌بلعد) گرفت؛yt-dlp برای URL های پخش‌کننده دست‌نخورده ماند.
- **رفع ۲ — بک‌فیل تاریخ-دقیق**: `scrape_apod_web(date=...)` حالا **همان روزِ درخواستی** را از فید پیدا می‌کند (نه جدیدترین را)؛ در دورهٔ placeholder بودن API، بک‌فیل `--date` نگهبان دیگر خطر پست‌کردنِ «جدیدترین» به‌جای روز غایب را ندارد و روزِ خارج از پوشش فید به‌جای جایگزین خاموش، None برمی‌گرداند.
- **رفع ۳ — قابلیت ارسال پوستر**: صفت `poster` تگ `<video>` به‌عنوان `thumbnail_url` استخراج می‌شود تا اگر ویدئو از سقف حجم گذشت، پیش‌نمایش تصویری پست شود.
- **رفع ۴ — سوءرفتار خاموشِ walkback در دوران API کهنه (دومین ریشه، کشف‌شده در اجرای زنده)**: کوئری «امروز» (بدون تاریخ) API حالا **HTTP 500** می‌دهد (سایت یک روز عقب است). کد قدیمی این ۵۰۰ را به‌معنای «مدخل امروز هنوز منتشر نشده» می‌گرفت و به walkback دیروز برمی‌گشت → رکورد دیروز که قبلاً پست شده → «already posted — nothing to do» → اجرا «موفق» ولی پست امروز هرگز نمی‌رفت. حالا **هر** خطای API (۵۰۰، شبکه و…) قبل از walkback بازیابی از وب را فعال می‌کند — فید RSS مرجعِ «APOD فعلی چیست» است و کوئری بدون تاریخ همان جدیدترین مقاله را برمی‌گرداند؛ کوئری `--date` هم دقیقاً همان روز را.
- **تست**: `test_video_day_fix.py` — ۳۸ چک روی fixture های واقعی امروز (صفحهٔ ویدئویی، صفحهٔ عکسی ۱۰-۱۵ و ۱۰-۱۴ برای رگرسیون، فید): بازیابی ویدئو، اولویت ویدئو بر کاندیداهای آشغال (لوگو)، سالم‌ماندن روزهای عکس، تاریخ-دقیق/بیرون-از-فید/جدیدترین، مسیر YouTube embedUrl، شبیه‌سازی زندهٔ ۵۰۰ روی «امروز» (بازیابی امروز، نه walkback دیروز) و روی `--date`، HEAD زندهٔ MP4 (۲۵٫۸MB < سقف)؛ dry-run سرتاسری روی `--date 2026-10-16` هم موفق (placeholder → recovery ویدئو → MP4 → پیش‌نمایش پست).

## تغییرات (۲۰۲۶-۰۹-۲۸) — فیکس انتخاب تصویر روزهای خاص

- **باگ**: در روزهایی که تصویر واقعی APOD حجم کمی دارد (مثل «لاته کیهانی» — یک رنگ سادهٔ ۹۶۰×۶۴۰ که فقط ۷٫۵ کیلوبایت فشرده می‌شود)، قاعدهٔ «حداقل ۱۰KB» تصویر اصلی را رد می‌کرد و نسخهٔ `_annotated` (که ناسا متن اطلاعیهٔ جابه‌جایی سایت را داخلش نوشته) جای آن پست می‌شد و در کانال «خراب» دیده می‌شد.
- **رفع**: اعتبارسنجی تصویر به‌جای حجم بایت، با باز کردن واقعی فایل (Pillow) و کنترل ابعاد (≥۴۰۰ پیکسل عرض) انجام می‌شود؛ کاندیداها به ترتیب اولویت (hdurl → نسخهٔ بدون `_annotated` → url) ارزیابی و انتخاب می‌شوند، نه بر اساس بزرگ‌ترین فایل.
- **ابزار ترمیم**: ورک‌فلوی `fix-media.yml` (اجرای دستی) عکس هر پیام پست‌شدهٔ کانال را با حفظ دقیق کپشنش (`editMessageMedia`) تعویض می‌کند؛ کپشن از فایل `fix-caption.txt` خوانده می‌شود.

## تغییرات (۲۰۲۶-۱۰-۰۱) — بازیابی APOD از وب + پاک‌سازی یادداشت‌های سایت

- **باگ ۱ (ریشه)**: در دورهٔ مهاجرت apod.nasa.gov → science.nasa.gov، API ناسا به‌جای رکورد واقعی پاسخ placeholder می‌دهد (عنوان «NASA Science» + لوگوی سایت) و همان شرح روز جاری را برای هر تاریخی که بخواهید برمی‌گرداند. نتیجه: پست بدون عکس با عنوان غلط (۰۹-۳۰ و ۱۰-۰۱).
- **باگ ۲**: اجرای پشتیبان با walkback به عقب، رکورد placeholder تاریخ دیروز را می‌گرفت (تاریخش با state نمی‌خواند) و همان محتوا را دوباره پست می‌کرد → پست تکراری شب ۰۹-۳۰ (پیام‌های ۱۲۳/۱۲۴).
- **باگ ۳**: جمله‌های متای APOD («ایمیل ارسال تصاویر تغییر کرده است»، «سایت اصلی جابه‌جا شد»، «تصویر فردا: ...») به ترجمهٔ فارسی نفوذ می‌کردند و در انتهای پست کانال دیده می‌شدند.
- **رفع ۱**: تشخیص placeholder (`is_apod_placeholder`) + بازیابی کامل رکورد واقعی از خود سایت ناسا (`scrape_apod_web`): صفحهٔ `/apod/` → جدیدترین مقالهٔ روزانه (`image-article/apod-YYYY-<ماه>-D-...`) → عنوان و تاریخ از og:title، تصویر اصلی از CDN (نسخهٔ اصل + fallback ها)، شرح، و اعتبار عکاس — همه با retry روی soft-404 های موقت CDN ناسا.
- **رفع ۲**: رکوردهای placeholder هرگز پذیرفته نمی‌شوند — نه پست می‌شوند و نه walkback روزهای عقب را فریب می‌دهند؛ اگر بازیابی از وب هم شکست بخورد، اجرا fail می‌شود تا cron پشتیبان دوباره تلاش کند.
- **رفع ۳**: اگر هیچ رسانه‌ای آماده نشد، اجرا به‌جای پستِ فقط‌متنی fail می‌شود (سیاست کانال: پست بدون عکس = پست خراب)؛ state.json هم دست‌نخورده می‌ماند.
- **رفع ۴**: الگوهای فرمولی یادداشت‌های متا (`APOD_META_SUBS`) قبل از ترجمه با regex های هدفمند حذف می‌شوند (هر دو variant وب‌سایت و API)؛ جمله‌های اصلی شرح — حتی جملهٔ پایانی داخل پرانتز — دست‌نخورده می‌مانند.
- **تست**: ۳۰ سناریوی رگرسیون (`scripts/test_apod_web_fix.py` محلی): تشخیص placeholder، پاک‌سازی متا در ۴ گونهٔ متن، بازیابی fetch با mock، اسکرپ زندهٔ وب، دانلود و decode تصویر — همه PASS؛ dry-run کامل روی روز جاری هم PASS.

## تغییرات (۲۰۲۶-۱۰-۱۰) — 🛡 نگهبان کانال + ریشه‌کن‌سازی رقابت state

- **نگهبان کانال (`channel_guardian.py` + workflow جدید)**: راستی‌آزمایی روزانهٔ واقعی کانال (از `t.me/s/daily_sciences`) به‌جای اتکای صرف به state — سه اسلات روزانه (۰۹:۵۵ / ۲۲:۱۰ / ۲۳:۰۵ UTC): پست غایب را با بات مربوطه پُر می‌کند، تکراری را حذف و سهمیه را ۱به۱ اصلاح می‌کند، APOD بدون عکس را حذف + پاک‌سازی state + ارسال مجدد می‌کند و اگر چیزی ترمیم‌ناپذیر بود exit 1 می‌دهد تا GitHub ایمیل بزند. روزهای جا‌ماندهٔ APOD هم با `--date` پُر می‌شوند (تاریخچهٔ `posted_dates` ۳۰روزه در state).
- **رقابت state ریشه‌کن شد**: هر سه workflow حالا در یک گروه concurrency مشترک (`channel-pipelines`) هستند — دیگر هیچ دو اجرایی (حتی بین ناسا و ردیت) نمی‌توانند چرخهٔ «خواندن state → پست → push» را هم‌زمان اجرا کنند. همین رقابت امروز باعث ۵ پست تکراری (پیام ۱۹۸-۲۰۲) شده بود که حذف شدند.
- **کلید طلایی برای پیش‌نمایش کانال**: `TELEGRAM_CHAT_ID` عددی است و URL پیش‌نمایش را خراب می‌کرد؛ `CHANNEL_USERNAME: daily_sciences` صریح در workflow نگهبان حلش کرد.
- **مقاوم‌سازی متادیتای ناسا**: پروب NASA API با fallback به DEMO_KEY؛ unreachable هرگز چک‌ها را غیرفعال نمی‌کند (فقط کانال+state را راستی‌آزمایی می‌کند).
- **تست**: `test_guardian_logic.py` — ۶۵ سناریوی آفلاین (پارس HTML واقعی، تطبیق تاریخ شمسی، کلیدهای نرمال‌شدهٔ فارسی، تکراری سه‌گانه، ترجیح جفت کامل، جراحی state، ۱۲ سناریوی dry-run فازها) — همه PASS؛ اجرای زندهٔ dry-run و واقعی روی Actions هر دو موفق.
